# Offline import candidate (preparation only)

`NativeMigrationImport.prepare(bundleURL:schemaURL:sqlURL:destinationURL:)` accepts the version-1 bundle and **trusted application** catalog/DDL. It reruns preflight and rechecks each input's count, size and hash while importing. Invalid/cancelled preflight produces no candidate. Incomplete inputs may produce a candidate with typed unresolved scopes; missing objects, credentials, jobs and native auxiliary tables are never reported as restored.

Only a new directory below the process's resolved temporary directory is accepted. Existing paths, symlinks and overlap with the input bundle are refused. The directory is private (0700), files are 0600, writes use pinned directory/file descriptors and exclusive creation. SQLite opens the already-created file through `/dev/fd/<fd>`, with a MEMORY rollback journal while building this disposable candidate; no existing path is opened writable. Errors/cancellation discard the entire created directory. Before the import transaction, the empty schema must occupy at most 16 MiB. The rollback journal holds before-images of that initial schema only; newly allocated record pages have no before-images, so journal storage does not grow with imported rows. No automatic application stop, destination replacement, Keychain write, external connection, hook, job enqueue or worker startup occurs.

The candidate contains `candidate.sqlite` with the 92 original model tables, `assets/<sha256>.blob`, source manifest/inventory copies and `candidate.json`. It has a `.native-migration-candidate` marker and is **not an application data directory**: it does not create `crm.sqlite`, native bootstrap metadata, native operational tables, or active document mappings. Imported asset locations and owners are recorded in a dedicated candidate-only table. External assets are retained in inventory and reported unresolved. Original credential ciphertext/pointers and job inventory are preserved but not activated or rewritten.

Every scalar is explicitly bound. Decimal and date text, JSON text, opaque String identifiers and binary data remain exact; arrays retain typed elements. Only fields identified by the trusted catalog's `@db.Uuid` are canonicalized to lowercase (including typed UUID-array elements). Each changed UUID value is counted. Unchanged input bundles retain original lexical text. The type basis is `prisma/schema.prisma` and PostgreSQL `UUID` DDL (for example `prisma/migrations/20260405150000_add_line_items/migration.sql`); lowercase output of a live PostgreSQL export has not been tested here. Arbitrary String IDs, embedded JSON strings and non-UUID String arrays are not lowercased.

All rows are read back through their normalized primary key and compared with bound values. Deferred foreign keys, unique/composite keys, all table counts and SQLite integrity are checked. Local assets are streamed with 64 KiB buffers and checked against hashes both before publication and from candidate files. The source manifest is checked again at the end. Successful preparation closes SQLite, returns it to DELETE journal mode, syncs files and directory metadata, and writes the completed result last. This proves a self-consistent candidate from a declared bundle; it does not establish the authenticity/completeness of the original production snapshot or perform application restore.
