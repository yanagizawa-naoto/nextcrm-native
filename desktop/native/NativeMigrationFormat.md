# Offline migration bundle, version 1

This is a **read-only preflight format**, not a backup archive or a completed migration. No source database, network service, normal application data, or Keychain is opened. An exporter/importer and a consistent online backup are separate work.

`manifest.json` contains `formatVersion: 1`, `schemaSHA256` (exact current `prisma/schema.prisma` hash), `source: {kind, snapshotID, consistent, completed, databaseNamespaceSHA256?}`, and `models: [{name, path, rows, bytes, sha256}]` for **every** catalog model, including empty models. `source.kind` is `web-postgresql`, `native-sqlite`, or `legacy-accounts`; only a complete Web relational export is covered by this format. Native auxiliary tables and a legacy accounts conversion require further work and are reported incomplete. A stable nonempty snapshot ID and both consistency flags are required; these are exporter declarations, not proof of a live source transaction. The model array may be in any order.

`assets`, `jobs`, and `secrets` are mandatory file descriptors `{path, rows, bytes, sha256}`; each points to UTF-8 NDJSON, including an empty file when there are no entries. All hashes are lowercase SHA256. Byte counts and row counts are nonnegative JSON integers within Int64. Every nonempty NDJSON line is one record and must end in LF. Blank lines, duplicate object keys in envelope records, unknown model/field names, and missing fields are invalid. A model row is an object with **all scalar Prisma field names** as keys, including nullable fields. `@map` SQL names are not accepted as field aliases.

Cells: SQL NULL is JSON `null`; String and enum are JSON strings; Boolean is JSON boolean; Int/BigInt/Decimal are decimal **strings** (no Double, exponent, leading plus); DateTime is canonical UTC `YYYY-MM-DDTHH:mm:ss[.1..6 digits]Z`, while `@db.Date` is `YYYY-MM-DD`. Years 0001–9999 and the proleptic Gregorian calendar are supported. Other PostgreSQL temporal values require explicit exporter handling and are rejected. Arrays are JSON arrays of typed non-NULL scalar cells. Json is `{ "json": "the exact JSON text" }`, distinguishing JSON null from SQL NULL and preserving large numeric lexemes. Bytes/pgvector are `{ "base64": "canonical base64" }`; pgvector is exactly 1536 finite little-endian float32 components. `tsvector` is preserved as text; its semantic equivalence and native search reindexing remain importer work. Decimal scale/precision are checked without floating point; PostgreSQL UUID comparison is case-insensitive without altering source text. String equality and key comparisons preserve UTF-8 identity. Compound uniqueness uses PostgreSQL NULL-distinct semantics.

An asset row is `{id, path, bytes, sha256, owners:[{model, key:{primaryKeyField:cell,...}, field}], storageKey}`. `path` is an included raw file; `storageKey` must match each owner's scalar field exactly. Known references (Documents.key/document_file_url/thumbnail_url, Invoices.pdfStorageKey, Invoice_Attachments.storageKey, Users.avatar/image) must have an owner entry. Optional `externalURL` replaces `path` for a non-included remote asset and is reported incomplete; it is never fetched. Every owner must exist and name a supported asset-reference field. A nonempty `ImageUpload` model is reported incomplete because its ID-only rows need an exporter-specific object-key inventory. Every local asset is streamed and hash/size checked; shared bytes may have multiple owners. Declared unreferenced assets are rejected so omission cannot be hidden as an unattached file.

A secret row is `{id, purpose, storage, valueSHA256?, owner?:{model,key,field}, namespaceSHA256?}`. `storage` is `server-aes256gcm`, `native-keychain`, `environment`, `password-hash`, or `opaque-auth`. `valueSHA256` for an owner hashes the raw UTF-8 string cell; secret bytes must **never** be placed in this inventory. Known credential/auth fields must have matching owner/digest entries; an owner must name one of those fields. `environment` entries have no owner. Generic settings/JSON/PluginData may embed additional secrets: their complete inventory is explicitly not proved. An optional injected secret-availability probe can return present/missing/unknown for supplied metadata only; the default never accesses Keychain and reports unknown. Known encrypted fields require the corresponding storage declaration: server AES-GCM envelopes have canonical Base64 and at least 12 IV + 16 tag bytes; native pointers require a supported prefix and UUID. Presence and envelope shape do not prove decryption or destination namespace access. Native namespace relocation, rotated/deleted keys, server encryption keys, and auth-cookie secret continuity remain explicit recovery obligations.

A job row is `{id, event, state, deliveryStarted, hasReceipt, policy, references:[{model,key}]}`. `state` is pending/retry/running/done/failed/cancelled/needs_review; `policy` is manual-review/rebuild/none. References must resolve. Completed or ambiguous external effects are never labelled safe to replay. This inventory does not read or translate Inngest/native runtime storage; its completeness is an exporter assertion, and all workers remain stopped.

Paths must be relative UTF-8 paths of at most 1024 bytes with no empty, `.`, `..`, NUL, backslash, or control-character components. All ancestors and leaves are opened with `openat` + `O_NOFOLLOW`, directories are pinned, leaves must be regular files, and inode/size/time metadata is rechecked after reading. Special files and symlinks are rejected. File descriptors, model rows, and assets are streamed; default chunks are 64 KiB, each NDJSON line is at most 8 MiB, manifest/catalog at most 4 MiB, JSON nesting at most 128, and retained diagnostics at most 200. Limit hits are explicit errors, never silent truncation. Relationship/unique/reference indexes use a private disposable SQLite file (1 MiB cache, file temp store), not an in-memory table of every record. Cancellation removes that temporary index and never modifies bundle contents.

Result JSON has `status` (validated/incomplete/invalid/cancelled), `migrationPerformed: false`, counts, Japanese diagnostics with stable codes and model/row/field locations, diagnostic totals, and unavoidable `limitations`. It does not echo cell values, storage keys, secret IDs, or full input paths. `validated` means structural checks within this declared format passed; it does not certify source completeness, a PostgreSQL engine round trip, Keychain restoration, functional attachments, safe worker resumption, or successful migration/restore. An importer must still compare source and destination and enforce a non-destructive publication/recovery policy.
